# Логирование PaperWeave

Этот документ задаёт локальное применение глобального требования к логам и каталог событий PaperWeave. Общие требования агентов находятся в `/home/denis/.agents/AGENTS.md`. Здесь описаны только проектные события и настройки.

## Канон

- Для backend используется общий модуль `paperweave.infrastructure.logging`: `configure_logging` настраивает форматирование, а `log_event` формирует события. Не создавать локальные форматтеры и не писать runtime-диагностику через `print`.
- События выводятся в stdout контейнера. При неприкреплённом выводе — одна JSON Lines запись на событие; в интерактивном TTY — краткая строка с UTC временем и общей цветовой семантикой уровней. `NO_COLOR` отключает цвета. Цвет никогда не является единственным представлением уровня.
- Каждая запись содержит `timestamp`, `level`, `service`, `event`, `message`. Дополнительные поля добавляются только когда они помогают расследовать конкретное событие.
- Время — ISO 8601 UTC. `event` — стабильный идентификатор на английском; `message` — короткое сообщение на русском. Ключи полей — `snake_case`.
- Чувствительные поля и вложенные словари обрабатываются общим редактированием. Это страховка, а не разрешение передавать чувствительный текст в logger.
- Запрещено записывать пароли, секреты, cookies, session ID, токены, email, тела запросов/ответов, содержимое рукописей, PDF, выделенный текст и AI prompt/response. Не включать значения конфигурации, DSN и содержимое загруженных файлов.
- Uvicorn access logging выключен: HTTP-сводка создаётся middleware через общий toolkit. Health-check маршруты исключены, чтобы проверки Compose не заполняли поток. Сервис UI пишет JSON access-события Nginx в тех же основных полях; `/_health` не логируется.

Уровень `ERROR` применяется к неуспешным системным операциям и HTTP 5xx; штатная валидация и пользовательские отказы сами по себе не считаются системными ошибками. `WARNING` используется для восстановимой деградации. Не логировать одно исключение на нескольких слоях.

## Поля событий

| Поле | Правило |
|---|---|
| `timestamp` | Время ISO 8601 в UTC; UI контейнер фиксирует `TZ=UTC` для Nginx |
| `level` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `service` | Имя Compose-сервиса (`api`, `ui`) |
| `event` | Стабильный код события, например `http.request.completed` |
| `message` | Краткое описание результата или сбоя на русском |
| `request_id` | Создаётся API middleware для HTTP-запроса и возвращается в `X-Request-ID` |
| `route`, `method`, `status_code` | Шаблон маршрута, HTTP-метод и результат запроса; без query string и тел |
| `duration_ms` / `duration_seconds` | Время HTTP-операции; единица указывается в названии поля |
| `error_type` | Класс ожидаемой технической ошибки без сообщения, которое может содержать данные |

## Каталог событий

| Event | Владелец | Условие | Уровень | Контекст и назначение |
|---|---|---|---|---|
| `app.started` | API lifespan | API завершил инициализацию локальных зависимостей | INFO | Подтверждает запуск процесса; не утверждает, что все downstream-зависимости уже проверены |
| `app.stopping` | API lifespan | Началась штатная остановка API | INFO | Отделяет остановку процесса от аварийного завершения |
| `http.request.completed` | API middleware | Завершился HTTP-запрос, кроме `/api/v1/health/*` | INFO; ERROR для 5xx | `request_id`, method, route, status_code, duration_ms; поиск медленных и неуспешных запросов |
| `http.request.completed` | UI Nginx | Завершился HTTP-запрос UI, кроме `/_health` | INFO; ERROR для 5xx | method, route, status_code, duration_seconds; сводка раздачи UI без query и тела |
| `profile.avatar.previous_file_cleanup_failed` | ProfileService | После успешной замены аватара не удалось удалить предыдущий файл | WARNING | Только `error_type`; профиль уже обновлён, предупреждение обозначает возможный осиротевший файл |

События `uvicorn.error` от runtime могут появляться при необработанных ошибках. Их не следует повторять в доменных слоях без дополнительной информации. При добавлении нового события обновить каталог и проверить, что поля соответствуют глобальным ограничениям.

## Чтение локальных логов

`make logs` следует за stdout/stderr Compose-сервисов. JSON-поля можно фильтровать обычными инструментами JSON Lines. Остановка наблюдения через Ctrl-C завершает команду просмотра и не означает ошибку приложения. Цветовой рендерер используется toolkit только при непосредственном интерактивном TTY; контейнерные JSON-события остаются без ANSI-кодов.
